C2Retarget profile(s) 'Default' from 'Passkey Pilot' to a group without adminsfixes R1, R4, R6

Entra allows a passkey if any scoped profile allows it, so a loose profile on a target that contains admins overrides their strict profile.

Before
{
  "target": "Passkey Pilot",
  "targetId": "g-pilot",
  "privilegedUsersCovered": [
    "oscar@northwind.example"
  ]
}
After
{
  "target": "Passkey Pilot (excluding privileged users)",
  "targetId": "ep-proposed-passkey-pilot-excluding-privileged-users",
  "members": 1
}

The proposed group is a static snapshot. In production, keep it current with a dynamic membership rule or by excluding your role-assignable admin groups from it.

C3Create profile 'Admins - device-bound, attested'fixes R1

Admins need a profile that only accepts device-bound, attested passkeys.

After
{
  "displayName": "Admins - device-bound, attested",
  "passkeyTypes": [
    "deviceBound"
  ],
  "attestation": "required",
  "keyRestriction": "none",
  "weakestCredential": "Device-bound, attested, any authenticator"
}

Add an AAGUID allow list for your approved security keys.

C4Scope privileged users to 'Admins - device-bound, attested'fixes R1
