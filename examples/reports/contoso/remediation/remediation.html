Proposed changes

C1Retarget profile(s) 'Default' from 'All users' to a group without adminsfixes R1, R4, R6

Entra allows a passkey if any scoped profile allows it, so a loose profile on a target that contains admins overrides their strict profile.

Before
{
  "target": "All users",
  "targetId": "all_users",
  "privilegedUsersCovered": [
    "alice@contoso.example",
    "bob@contoso.example",
    "carol@contoso.example",
    "erin@contoso.example"
  ]
}
After
{
  "target": "All users (excluding privileged users)",
  "targetId": "ep-proposed-all-users-excluding-privileged-users",
  "members": 2
}

The proposed group is a static snapshot. In production, keep it current with a dynamic membership rule or by excluding your role-assignable admin groups from it.

C2Scope privileged users to 'Admins - device-bound'fixes R1

Every admin should be scoped to the strict profile, and only to it.

After
{
  "target": "Privileged users (passkey admin profile)",
  "profile": "Admins - device-bound",
  "users": [
    "erin@contoso.example"
  ]
}

Prefer targeting your existing role-assignable admin group instead of this snapshot group.

C3Point the registration campaign at passkeys for all users, with limited snoozesfixes R8

3 SMS/voice-only user(s) need a nudge before their deadline.

Before
{
  "state": "enabled",
  "snoozeDurationInDays": 1,
  "enforceRegistrationAfterAllowedSnoozes": false,
  "targets": [
    "All users"

  "enforceRegistrationAfterAllowedSnoozes": true,
  "targets": [
    "All users"

Check the targetedAuthenticationMethod value your tenant's Graph version accepts.

C4Require 'Admins - device-bound keys only' for admins on all appsfixes R11, R12

Conditional Access must be satisfied by every applicable policy, so one strict policy closes the sign-in gap left by plain MFA or the built-in phishing-resistant strength (which accepts synced passkeys).

Before
{
  "adminsWithWeakGate": [
    "alice@contoso.example",
    "bob@contoso.example",
    "carol@contoso.example",
    "erin@contoso.example"
  ]
}
After
{
  "authenticationStrength": {
    "name": "Admins - device-bound keys only",
    "allowedCombinations": [
      "fido2",
      "windowsHelloForBusiness",
      "x509CertificateMultiFactor"
    ],
    "fido2AllowedAAGUIDs": [
      "a4e9fc6d-4cbe-4758-b8ba-37598bb5bbaa",
      "cb69481e-8ff7-4039-93ec-0a2729a154a8",
      "ee882879-721c-4913-9775-3dfcce97072a"
    ]
  },
  "policy": "Admins: device-bound keys only (EffectivePasskey)",
  "target": "Privileged users (sign-in and TAP)",
  "breakGlassExcluded": "not targeted"
}

Roll out in report-only first and check sign-in logs for admins without an approved key.

Emergency-access accounts are left out on purpose; protect them separately.

C5Exclude admins from Temporary Access Pass and make TAP single-use, 60 minutesfixes R13

Anyone who can issue an admin a TAP can register a passkey on that account.

Before
{
  "isUsableOnce": false,
  "maximumLifetimeInMinutes": 480,
  "excluded": []
}
After
{
  "isUsableOnce": true,
  "maximumLifetimeInMinutes": 60,
  "excluded": [
    "Privileged users (TAP excluded)"
  ]
}

Issue admin TAPs only through a documented, two-person process, by temporarily removing the admin from this group.

C6Replace 'CA exclusions (legacy apps)' with a role-assignable groupfixes R14

Only Privileged Role Administrators can change a role-assignable group, so owners and Groups Administrators can no longer move admins in or out of policy scope.

Before
{
  "group": "CA exclusions (legacy apps)",
  "isAssignableToRole": false,
  "owners": 1,
  "membershipRule": null
}
After
{
  "group": "CA exclusions (legacy apps) (role-assignable)",
  "isAssignableToRole": true,
  "owners": 0,
  "members": 1
}

isAssignableToRole can only be set when a group is created, so this is a new group.

C7Complete the authentication methods migrationfixes R15

Legacy MFA and SSPR settings keep governing SMS and voice until the migration is marked complete.

Before
{
  "policyMigrationState": "migrationInProgress"
}
After
{
  "policyMigrationState": "migrationComplete"
}

Check that the methods policy enables everything users rely on before you complete it.
